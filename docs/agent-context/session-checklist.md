# Session Checklist — Active Copilot Hot-spots

> **Read this file at session start** after `docs/agent-context/project-overview.md`. It lists the top Copilot catch categories from the last 30 days so the agent can pre-audit for these patterns **before** writing code, not after Copilot flags them.
>
> **Regeneration model.** `.github/workflows/distill-learnings.yml` regenerates the Top-3 table weekly. It overwrites the **category list, counts, ordering, and `_Last updated:_` timestamp** every run, but **preserves the "Mitigation before pushing" cell verbatim** for any category that is still present in the new top-3. Treat the table as a hybrid:
> - **Auto-generated (do NOT hand-edit):** the category names, counts, order, and the `_Last updated:_` line.
> - **Hand-curated (DO edit):** each row's "Mitigation before pushing" cell. When a category becomes a new hot-spot, the workflow seeds it with a dated `_New category ... — add mitigation_` placeholder; replace that placeholder with a concrete mitigation drawn from the matching entries in `COPILOT_LEARNINGS.md`. Your edit will survive every subsequent regeneration until that category drops out of the top-3.
>
> Everything outside the Top-3 table (the "Full categories" section, the "How to use this file" section, the exit criteria) is hand-curated and the workflow does not touch it.

## Full categories (all-time, any count)

When auditing an unfamiliar area, scan these too:

- `accessibility` — icon-only buttons need `aria-label`; toggle buttons need `aria-pressed`; don't rely on `title` alone.
- `docker` — Railway deploy layer caching; `node:22-slim` needs Chromium libs for PDF export (see Dockerfile apt-get block).
- `dependencies/semver` — ESLint v6 pin in `package.json` overrides; Hono major-version compatibility.
- `graphql/pagination` — always fetch `totalCount` with `first: N`; block or paginate at the ceiling.
- `i18n` — every user-visible string (`toast`, `aria-label`, `placeholder`, JSX text, error messages thrown into user-visible slots like `exportErrorMsg`) must route through `useTranslations` / `getTranslations`, in both `messages/en.json` and `messages/es.json` in the same commit.
- `performance/unifier-client` — `fetchAllRows()` needs a `maxRows` cap; never fetch unbounded then filter in memory.
- `prisma/transactions` — use array-form `$transaction([...])`; interactive transactions are incompatible with Railway's PgBouncer.
- `react/state-sync` — useEffect dependencies that feed into useCallback references; avoid stale closures over filters that change between renders.
- `security/dev-bypass` — `isDevToolsAllowed()` is a production guard, not an auth check; every DevTools method needs `requireDevToolsAdmin()`.
- `security/input-validation` — Zod schemas on Unifier/external data: use `.default("")` or `.optional()`, never `.string().min(1)` for fields Unifier can return null.
- `shell/safety` — avoid backticks, `**`, em-dashes in `run:` blocks; build the string with `printf` into a variable first.
- `testing/fixtures` — every API that consumes external data must have an integration test fixture where each nullable field is `null`/`""`/omitted.
- `typescript/i18n-navigation` — `next-intl` locale-prefixed routes use `navigate` from `@/i18n/navigation`, not raw `router.push("/en/...")`.
